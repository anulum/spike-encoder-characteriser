# Data and authority boundaries

## Present tooling

The maintained checkout and selected development environment are execution inputs for repository controls. Received descriptors, dependency receipts and generated inventories cannot nominate acceptance policy or executables. Checks inspect bounded local scopes and report fixed diagnostics. Byte identity is not scientific correctness, current trust, global registration, reproducible-build proof or hosted qualification.

A source inventory is not a concurrent filesystem snapshot or a power-failure durability guarantee. Native child processes use maintained finite argument vectors and direct-child deadlines; completed-output limits are not live volume ceilings. Full foundation qualification remains in progress.

## Future characterisation inputs

Continuous data, labels, normalisation, encoder controls, rasters, spike-log containers, fitted decoders and evidence references are supplied data. They do not grant program execution, signing, publication or device authority. Input shape, source capability, original-record completeness, output destinations and resource limits require admission before values or allocation.

A missing record is not an empty record. A retained partial container cannot grant complete-population metrics. Training/evaluation separation, signed information loss, model/physical clocks and stochastic independence need actual source/measurement evidence. New attempts preserve prior failures; read-only reports cannot repair or reseal results.

Installed provider compatibility, current trust, actual decoder/probe accuracy, process recovery and physical fabric qualification remain unimplemented domain boundaries. No runtime isolation, numerical reliability, device control or operational recovery guarantee is claimed.
