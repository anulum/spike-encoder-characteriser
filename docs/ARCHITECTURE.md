# Repository architecture

## Current executable tooling

The repository contains metadata, source-provenance, workflow, dependency-alignment, documentation, inventory and preflight controls, plus native-tool bootstrap. Commands inspect fixed declared scopes; received metadata cannot choose another policy or grant scientific eligibility. The foundation remains under qualification.

## Planned characterisation boundaries

| Component | Responsibility | Required evidence |
| --- | --- | --- |
| Stimulus admission | Exact continuous-source bytes/generator, licence, original record inventory, units and normalisation | Hash-bound complete inputs and explicit sample/channel maps |
| Adapters | Invoke seven actual source functions with supported effective controls | Complete direct-call output equality and supported-shape/refusal evidence |
| Runner | Execute every prespecified point/trial and preserve failures | Complete plan/output/attempt population and bounded recovery |
| Reconstruction and probe | Training-only features, fit and held-out evaluation | Independent references, split isolation and complete raw losses/predictions |
| Metrics and Pareto | Exact declared denominator, units, censoring and comparable bounds | Complete original-record output and admitted method/reference evidence |
| Evidence and reports | Installed providers and read-only consumers | Real source/producer/consumer and complete current qualification |

Five software families accept buffered flattened vectors with a model window; delta and sigma-delta accept complete time sequences with thresholds. Activity can lose polarity, rank ties can depend on the actual pinned sort, and source-unsupported controls remain inconclusive. A separate fabric extension requires actual native capture and timing qualification.

The planned native result has fourteen top-level fields. Complete matrix and raw population identities remain referenced data, not invented result members. Intended public commands are list, run, report and compare. A separate installed-library parent consumer smoke must exercise an actual family and complete native result. No domain operation exists here yet. Read [validation tooling](validation-tooling.md) for the current executable interfaces.
